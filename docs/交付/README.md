## 重新生成

改完 HTML 后跑：

```bash
# 需要带 python-docx 的解释器，系统 python3 里通常没有
/Users/xingranya/.workbuddy-ai/binaries/python/envs/default/bin/python docs/交付/build_docx.py
```

脚本做五件事：图片转 base64 内嵌、调 HTML→DOCX 转换器、补齐字体属性、给一级标题加段前分页、打开目录域的自动重算。

几个不是可选项的细节：

1. **图片必须内嵌。** 转换器读不到 `file://` 路径，会静默丢图，而校验仍报「缺失 0」。脚本把 PNG 转成 base64 再交给转换器。
2. **字体属性要补全。** 转换器只写 `ascii` / `eastAsia`，`hAnsi` 与 `cs` 留空。Word 一般能兜住，别的渲染器会回退到无中文字形的字体，整页中文变空白。
3. **目录要独立分节。** 封面与目录各占一个 `<section role="cover">`，正文包在 `<section role="body" data-page-restart="1">` 里，页码才从正文重新起算。缺这层，转换校验会直接失败。
4. **分页不要重复加。** 正文首个一级标题紧跟分节符，若再加「段前分页」会多出空白页；脚本只给第二个及以后的一级标题加分页。
5. **目录页码要让它重算。** 转换器写出的目录是真正的 TOC 域，但缓存页码全是 1（转换时拿不到最终分页）。脚本往 `settings.xml` 里插 `w:updateFields`，Word 打开时用真实字体重排并刷新页码；元素必须插在 `w:compat` 之前，否则不满足 `CT_Settings` 的顺序约束。
